# Formato de MISSION.md

`MISSION.md` reside na raiz do workspace. Ele registra o _motivo_ pelo qual o usuário está aprendendo este tópico. Toda decisão de ensino — o que ensinar a seguir, quais recursos apresentar, quais exercícios elaborar — deve remeter a este documento.

## Modelo (Template)

```md
# Missão: {Tópico}

## Por quê
{1 a 3 frases. O objetivo concreto no mundo real que o usuário está buscando. O que muda na vida ou no trabalho dele quando tiver essa habilidade? Evite formulações abstratas como "compreender X" — busque o resultado subjacente.}

## O sucesso se parece com
- {Uma ação específica e observável que o usuário será capaz de fazer}
- {Outra ação específica}
- {…}

## Restrições
- {Tempo, orçamento, compromissos prévios, preferências de aprendizado, qualquer coisa que limite a abordagem}

## Fora de escopo
- {Tópicos adjacentes que o usuário explicitamente não deseja buscar agora — protege a zona de desenvolvimento proximal}
```

## Regras

- **Uma missão por workspace.** Se o usuário quiser aprender duas coisas não relacionadas, trata-se de dois workspaces.
- **Concreto em vez de abstrato.** "Correr uma meia maratona até outubro" supera "ficar mais em forma." "Entregar uma CLI em Rust para minha equipe" supera "aprender Rust."
- **Conteste a vagueza.** Se o usuário não conseguir articular o porquê, entreviste-o antes de escrever qualquer coisa. Uma missão ruim é pior do que nenhuma missão.
- **Revise quando a realidade mudar.** As missões mudam. Quando o objetivo do usuário mudar, atualize este arquivo — não deixe uma missão desatualizada orientar as sessões futuras.
- **Mantenha-o curto.** Se `MISSION.md` ultrapassar uma tela, deixou de ser uma bússola e passou a ser um plano.
